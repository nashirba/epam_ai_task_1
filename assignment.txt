- Choose any idea you like for an AI tool with RAG. Think about a dataset you will use to extend your app with RAG (this may be texts, links, or anything else you choose). Create an .md file with the project description (main idea, concepts, design details, dataset concept, system technical details, requirements, and limitations).
- Prepare (create or gather) source data (initial) files for your dataset. If you have few ideas for real and free data, you may use an LLM to help you consult and generate the dataset. Keep in mind, the dataset might not be large, but it must be representative and well-annotated.
- Select and run locally a database of your choice. It should provide storage and vector search capabilities. You may use any free software, and refer to some articles here. You may use Docker with free DB images from Docker Hub or run a database from source. (To run Docker on Windows, WSL may be used).
- Create an embeddings client that will create a searchable vector for any data chunk you need. You may use any embedding models (e.g. text-embedding-ada-002 or newer) and choose a reasonable embedding vector size.
- Fill the database with your dataset data in a searchable format. It is normal to use some script automation that prepares the data, creates embedding vectors for it, and uploads them to the DB.
- Create an LLM client to DIAL, or another LLM provider that will provide you with base Gen AI capabilities. Make sure the client can handle simple request–response interactions from AI.
- Implement the UI of your choice and make sure you can pass user input from it to the LLM and display results back. You can use any UI technology, from CLI or REST API to GUI or WebApp. Some of the most popular for fast prototyping are CLI and Python Streamlit.
- Join you RAG system:
--- The chosen UI
--- Conversion of the user input to embeddings as the search input
--- Search in the database for the most relevant data by using the vectors
--- Pass to the LLM the original user input and the documents found by vectors in one context window, and display back the AI response

RAG Practical task: Acceptance criteria and Scoring
- Factual (formal) implementation of all 9 steps above (note: each step must result in some artifacts reflected in your Git repository) grants you 80 points out of a maximum of 100.
- Note: If you skip embeddings and use simple full-text search instead, this will give a penalty of -10 points. But, if the final solution works and enhances LLM knowledge with the data from your dataset, this is still a RAG-based system, thus it will be scored as 70 points, which is the minimal pass.
- Based on the quality of the results, the original idea, technologies and requirements chosen, and implementation, the task results score may be increased up to 90–100 points.
