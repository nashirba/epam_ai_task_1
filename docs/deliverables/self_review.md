# Self-Review — Personal Investment-Planning Assistant

- **Project:** Personal Investment-Planning Assistant (PIA)
- **Author:** Nurlan
- **Status:** Submission self-review (post-Phase 11; pre-video).

## 1. What we built

A local, multi-agent investment-planning assistant for a Kazakhstan-resident individual investor: three Pydantic-typed agents (Portfolio, Market, Planner) collaborate over an in-process message bus to answer holdings, market, and reallocation questions with citations and a non-removable disclaimer. Knowledge comes from a real KZ-domain corpus (NBK rates, KASE quotes, bank deposit sheets, Almaty real-estate listings, RU+EN news, plus the user's own holdings/plan/notes) indexed in self-hosted Weaviate with hybrid search; live market data comes from a custom `kz-data` MCP server (4 tools) plus a consumed Tavily web-search MCP. A safety facade (rate-limit → sanitize → PII-redact → planner.run → output guardrail), a Langfuse tracing adapter, and a Streamlit UI with citation chips, allocation/currency donut charts, and a freshness pill close out the MVP+.

## 2. What worked well

- **Three agents with deliberate roles, not theater.** Portfolio (RAG), Market (MCP), Planner (orchestrator) is the smallest topology that satisfies the brief substantively. ADR 0004 walks through why a fourth News agent or a Compliance agent would be theatre, and the implementation honors that — `advise()` is the only user-facing entry, and the other two agents never call each other.
- **Typed Pydantic message bus catches drift early.** `AgentMessage`, `Citation`, `MarketSource`, `Recommendation` are real load-bearing types. The disclaimer being a Pydantic default field on `Recommendation` (not a model-discretion string) is what guarantees presence even on tool failure — verified by `tests/unit/test_planner_disclaimer.py`. Citations propagate through closure-based ledgers in `_make_planner` rather than being re-derived after the fact.
- **Custom MCP, not just consumption.** Building `kz-data` with FastMCP (4 tools, snapshot-backed) demonstrates protocol mastery and isolates KZ-specific data fetching from agent code. Combined with consuming Tavily, this hits both sides of the MCP rubric — see ADR 0005.
- **Local-first RAG with multilingual embeddings.** Self-hosted Weaviate (one Docker container) plus `BAAI/bge-m3` embeddings (free, multilingual) plus `LLM_MODEL=gemini/gemini-2.0-flash` (free hosted) gives a real `$0` reproducible grader path. ADRs 0006/0007/0008 walk through the abstraction so the same code runs on paid Sonnet 4.6 for the demo.
- **Safety as a structural facade plus an ADR-disciplined evolution.** Layered safety (sanitize / PII / rate-limit / guardrail) lives in pure functions under `src/pia/safety/`, each independently unit-tested. Twelve ADRs (0001-0012) cover the meaningful decisions, with ADR 0012 closing the v1 set by formalising the evaluation harness (thresholds, live-LLM gate, persisted-run schema); the post-draft plan stayed on rails because rationale lived in the repo, not the chat history. The adversarial suite (7 scenarios, `tests/adversarial/`) plus integration eval (hit-rate@5, faithfulness LLM-judge) provides honest evidence — not a "we tested it" hand-wave.

## 3. What we cut and why

Cuts trace back to either explicit non-goals in `docs/requirements_addendum.md` / `docs/superpowers/specs/...design.md` §2, or items deferred from `docs/draft-issues.md`. The cuts are honest, not aspirational.

- **Live data refresh.** Snapshots committed under `data/public/` are refreshed manually via `scripts/snapshot_news.py`. A live refresh job (cron-like or webhook-driven) is straightforward future work but adds a moving part that does not pay off in the v1 demo. Per ADR 0002 §non-goals.
- **Crypto / gold / UAPF / AIX bonds / mutual funds.** Out of v1 scope per ADR 0002. The user's actual exposure is in the v1 asset classes (KZT/USD deposits, Almaty real estate, KASE equities, US ETFs); broader coverage is a "next steps" item for the executive summary, not a v1 cut.
- **Multi-user / authentication.** The system runs as a single-user local Streamlit on `localhost`. No auth means no session storage, no isolation, no `/auth` surface — and that's the intended v1 framing per ADR 0002 and the meeting Q&A. Adding auth would force a deployment-shape change (server, sessions, per-user data isolation) that is disproportionate to the capstone.
- **Cross-encoder reranker.** Listed as optional polish in ADR 0008 and `docs/draft-issues.md`. The hybrid search (BM25 + dense, `alpha=0.5`) already clears the hit-rate@5 ≥ 0.6 threshold against `tests/fixtures/retrieval_labels.yaml`, so the reranker would be performance-tuning without a measurable win at this corpus size.
- **Resource-usage CPU / memory tracking.** Latency, request count, and tool-error / refusal rate are now exposed (in-process `Registry` in `src/pia/observability/metrics.py`, surfaced in the Streamlit Diagnostics expander on 2026-05-05). Memory and CPU counters specifically are still missing — Langfuse covers token usage when keys are set, but neither layer ships memory / CPU / hosted-LLM-quota gauges. Real OS-level resource metrics would need `psutil` or a separate exporter, which is disproportionate at single-user scale.
- **Cross-encoder reranker.** Listed as optional polish in ADR 0008 and `docs/draft-issues.md`. The hybrid search (BM25 + dense, `alpha=0.5`) already clears the hit-rate@5 ≥ 0.6 threshold against `tests/fixtures/retrieval_labels.yaml`, so the reranker would be performance-tuning without a measurable win at this corpus size.

Items that *were* cut in earlier drafts and have since closed (so future-you reading this knows they are no longer "what we cut"): MCP subprocess pooling per `advise()` call (ADR 0005 addendum); in-app diagnostics tab (Streamlit `diagnostics_view`); explicit Langfuse trace-id correlation per request (ADR 0010 addendum); ADR-0012 evaluation-harness contract; persisted eval-runs harness (`scripts/eval_report.py` shipped 2026-05-10, first run at `docs/eval-runs/2026-05-10-gemini-gemini-2.0-flash-all.json`).

## 4. What we would change with another week

Several items from the earlier draft of this section have shipped since (see end of §3). What remains:

- **Re-run the persisted eval harness on a paid model.** `scripts/eval_report.py` shipped 2026-05-10 against the ADR-0012 schema; the first committed run (`docs/eval-runs/2026-05-10-gemini-gemini-2.0-flash-all.json`) used the free-tier `gemini/gemini-2.0-flash` path and recorded a real `hit_rate@5 = 1.0` plus an honest provider-quota exhaustion for the faithfulness and adversarial suites. A rerun on `claude-sonnet-4-6` (or any paid model) would populate the live-LLM blocks and let the executive summary cite a single fully-passing run instead of carrying a free-tier-caveat paragraph. ~half a day plus quota.
- **Live news refresh job + provenance hardening.** Replace the manual `scripts/snapshot_news.py` flow with a small scheduler (apscheduler in-process, or a `cron` snippet) that refreshes news daily and updates the freshness pill from the actual file mtime. Combined with unwrapping Tavily's `content` field for richer provenance. ~1 day.
- **Cross-encoder reranker behind `RERANK=true`.** Measure the lift on hit-rate@5 against the labeled set; only ship if the lift > 0.05 (otherwise document as "tried, not worth it"). ~half a day.
- **OS-level resource gauges (memory, CPU, hosted-LLM quota).** The in-process `Registry` covers latency and call counts; `psutil`-backed gauges or a small exporter would close the last gap from `non_functional_requirements.md`. ~half a day.
- **Polish the demo shot list.** Three queries (holdings, market, reallocation) plus one adversarial probe (definitive-call refusal) plus one degraded-path probe (kill the MCP subprocess mid-call). Edit captions for the Russian queries. The script is in `docs/superpowers/plans/2026-05-02-pia-post-draft.md` Phase 14; recording is the missing artifact.

## 5. Lessons

- **Vibecoding works only when the rationale lives in the repo, not in the chat.** Twelve days of AI-assisted iteration would have lost coherence without the ADR discipline. ADR 0001 itself was the leverage: every meaningful choice (topology, MCP strategy, embeddings, observability, safety) got a numbered file, written at the time of the decision. When a later phase asked "why TEXT and not DATE for `published_at`?" — ADR 0009 answered, no chat archeology required. The price of an ADR is a few minutes; the saved dead-ends across 16 days easily paid for it.
- **ADR-driven planning beats spec-driven for AI-assisted work.** The full design spec (`docs/superpowers/specs/...design.md`) is necessary for the grader to read top-to-bottom — but during implementation, ADRs are the unit of decision. A plan phase that referenced "ADR 0011 §layer-order rationale" produced consistent code; a plan phase that referenced "the spec says safety should be layered" was vague enough to drift.
- **Free-tier engineering is real engineering.** The `$0` grader path forced disciplined choices: local embeddings (no per-token spend on indexing), LiteLLM abstraction (free Gemini Flash for CI; paid Sonnet 4.6 for demo), self-hosted Weaviate (no managed-service quota), Langfuse no-op when unconfigured. Every one of these survived contact with reality because the tradeoffs were taken seriously up front, not bolted on as a "free mode" afterthought.
- **Safety in financial assistants is structural, not stylistic.** A model-generated disclaimer can be regenerated away. A Pydantic default field cannot. A model-told "don't issue buy calls" can be jailbroken. A `guardrail_output()` that prepends `"Hedged note: "` on EN and RU verbs cannot. A model-promised "I won't reveal credentials" can leak in adversarial prompt-injection scenarios. A regex that redacts `hunter2` to `[REDACTED]` will not. ADR 0011 makes this explicit: every safety check is a pure function in its own module, idempotent, independently unit-tested.
- **Testing LLM behavior requires gates, not skips.** The fast unit suite mocks LLMs and never depends on a network. The integration and adversarial suites require `PIA_LIVE_LLM=1` and a key, and they are skipped without it — but they still run on the maintainer's machine and on the demo recording. Hard-coding the gate behind a marker (`@pytest.mark.adversarial`) plus an env-var skip-if pattern keeps CI fast while making "did you actually test this?" answerable with a `pytest -m adversarial` log.
