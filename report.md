# Copilot Metrics Report

## Summary
This project implements an Orders Management REST API using Python, FastAPI, SQLite, and SQLAlchemy.  
The API supports creating, reading, updating, deleting, and listing orders with pagination and filtering.  
GitHub Copilot was used extensively to speed up development, especially for boilerplate code and test generation, while manual review and fixes were required for validation logic and edge cases.

---

## Copilot Contribution & Metrics

- **Estimated Copilot contribution:** ~97%
- **Acceptance rate:** ~84%
- **Estimated time saved:** ~5–6 hours

These estimates are based on Copilot’s inline suggestions, generated code blocks, and test scaffolding during development.

---

## What Copilot Generated vs What I Fixed Manually

### Generated by Copilot
- Initial project structure (app/, tests/)
- FastAPI app setup and route skeletons
- SQLAlchemy model and Pydantic schema drafts
- Basic CRUD operations
- Initial pagination logic
- Majority of pytest test cases (happy paths)
- README draft structure

### Manually Fixed or Improved
- Added edge-case tests not generated by Copilot
- Asked Copilot to analyze requirements again and refine the code. Repeated several times.

---

## Edge Cases Added Manually
The following edge cases were added manually because they require business logic understanding beyond basic code generation:

1. Updating an order with an empty request body (returns 422)
2. Invalid amount filter range where `min_amount` is greater than `max_amount`
3. Invalid date range where `start_date` is after `end_date`

These tests helped catch subtle bugs and improved overall API reliability.

---

## 3 Key Learnings

1. **Copilot is best for scaffolding and repetition**  
   It significantly sped up writing boilerplate code, schemas, CRUD functions, and initial test cases.

2. **Copilot struggles with business logic and edge cases**  
   Logical validations like conflicting filters require review and refactoring by Copilot.

3. **Best results come from combining Copilot with frequent testing**  
   Writing clear comments, reviewing suggestions carefully, and running tests often led to higher-quality code.

---

## Conclusion
GitHub Copilot was a strong productivity tool for this project, reducing development time and helping generate large portions of the codebase. However, manual review and testing were essential to ensure correctness, proper validation, and alignment with task requirements.
